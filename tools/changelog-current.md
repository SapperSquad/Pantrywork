**0.10.0 - Forge 1.20.1, and an answer that had been wrong since August.**

**New: a Forge 1.20.1 file.** It is the fifth file on this page and it does not replace anything - the four 1.21.1 / 26.x files are unchanged at 0.9.0. Like the Fabric and 26.x files it is pure data: no classes, no code, nothing to install on the client. Drop it on the server and every player gets it.

**Why it exists now, when the page said for two months that it couldn't.** The old answer was that 1.20.1 has no food tags to extend - that the shared vocabulary there is `forge:`, and `forge:` only documents five crops: beetroot, carrot, nether wart, potato and wheat. That is true of the *platform*. It is not true of the mods. Farmer's Delight's 1.20 branch declares **64** `forge:` tags of its own - milk, dough, pasta, grain, eggs, berries, bread, the four raw and four cooked meats, cabbage, onion, rice, tomato - in exactly the two-level shape it later rebuilt under `c:`. On 1.20.1 the food mods extended `forge:` themselves, the same way they extended `c:` afterwards. Across the nineteen 1.20.1 jars that got read for this: **957 `forge:` item-tag files, 336 distinct food tag paths**. There was a vocabulary to bridge the whole time; the old answer quoted the documentation instead of reading the jars, which is the one thing this project has a standing rule against.

So this is a port, not a new mod. The taxonomy and the fair-swap rule are the same ones the 1.21 files use, and so are the price judgments behind them - except where the mods themselves are at different versions on 1.20.1, which is often. 39 price floors and 4 item prices were re-read out of 1.20.1 recipes rather than copied forward, because a recipe that changed between versions would have quietly moved a swap from fair to unfair.

**The roster on 1.20.1 is 21 mods, not 24.** Pam's HarvestCraft 2 **Crops** and **Trees** have no Forge 1.20.1 build at all - their only 1.20.x builds ask for a newer mod loader than 1.20.1 ships, which was measured by trying to boot them, not assumed - and **Bountiful Fares** is Fabric-only on that version. Everything else on the roster is there: Farmer's Delight, Croptopia, Pam's Food Core and Food Extended, Ocean's Delight, End's Delight, all three Let's Do mods, Aquaculture 2, Brewin' & Chewin', Create, Fish of Thieves, Refurbished Furniture, Kaleidoscope Cookery, Hearth and Harvest, Cultural Delights, Cook's Collection, Rustic Delight, Hybrid Delights, Oh The Biomes We've Gone and Origins.

**The same mess is there to clean up.** Seven spellings of cheese and seven of milk in the shared namespace, with two cross-references between the cheeses and five between the milks. Four spellings of onion with **zero** references between them. Hearth and Harvest files its cheese slices in `forge:foods/cheese`, which **nothing else on 1.20.1 reads** - so its cheese is invisible to Pam's and Meadow's cheese recipes until something bridges it. That is the same fix this mod was written for, one version down.

What that looks like once this file is in:
- Hearth and Harvest's cheese slices reach Pam's `forge:cheese` and Croptopia's `forge:cheeses`, so the recipes that only ever took their own mod's cheese now take theirs.
- **Kaleidoscope Cookery's wok lights on six mods' oil** - its own, plus Cook's Collection, Croptopia's olive oil, Hearth and Harvest, Pam's and Rustic Delight. The wok checks that one tag before it will cook anything, so all 225 of its wok recipes sit behind it.
- Salt stops being three separate items: Croptopia's and Pam's salt reach the tag Hearth and Harvest reads, and Hearth and Harvest's reaches theirs.
- Croptopia's strawberry and Farm & Charm's both land in the shared fruit tag, and neither one gets there by way of the other - so removing either mod does not take the other's strawberry with it.

**What you don't get, compared with the 1.21.1 file.** Being plain about this rather than letting the version tags imply parity:

- **19 of the conditional swaps are dropped.** Some swaps are only fair when a particular mod is installed - a cheap dough is fine next to Farm & Charm, which also sells cheap dough, and unfair next to Croptopia, which doesn't. On 1.21 those ship as a conditional overlay that the game applies only while the rescuing mod is loaded. **Minecraft 1.20.1 has no such thing** - overlays arrived in 1.20.2, and the conditional kind later still. Shipping those swaps unconditionally would put underpriced items into recipes with no rescuer in sight, which is exactly what the fair-swap rule exists to prevent, so on 1.20.1 they are left out instead. Affected: Pam's cheese, four cheap doughs, three milk bottles, three salts, Hearth and Harvest's flour and corn meal, Farmer's Delight's cabbage leaf, Farm & Charm's chicken parts and Kaleidoscope's sashimi.
- The measured consequence, since it is easier to trust a number than a rule: with Farm & Charm installed, the 1.21 file unifies **six** doughs in Croptopia's dough tag. On 1.20.1 that tag holds **two**. Everything else about dough still works - the other shared dough tag has all six on both versions.
- **No `PantryworkTagKeys`.** The API class compiles against 1.21.1 types, so the 1.20.1 file ships tags and nothing else. Mod authors on 1.20.1 reference the tags by id, which works the same way and is what the class was a convenience for.
- Minecraft 1.20.1 only, and Forge only. It is not tagged for NeoForge 1.20.1, which was not tested.

**Verified the same way everything else here is: on a running server.** A Forge 1.20.1 server was built for this file specifically. With the file alone: **50 assertions pass, 0 fail, and the log has no errors of any kind.** With 16 of the roster mods loaded alongside it: **338 pass, 0 fail**, across 83 tags. The other five - Create, Fish of Thieves, Refurbished Furniture, Hybrid Delights and Oh The Biomes We've Gone - each need a further library mod to start, so they are bridged from their own 1.20.1 jars but were not part of that boot; their entries are the ones this file is least able to promise. A third boot runs the identical mod set with Pantrywork *removed*, to prove that the errors those mods log are theirs and not this file's - the error list comes back identical, 31 for 31, and no error on any boot names Pantrywork.

One more check worth describing, because a test suite that cannot fail proves nothing. The single biggest hazard in this port is that 1.20.1 keeps its tag files in a folder named `tags/items/` where 1.21 uses `tags/item/`, and each is silently ignored on the other version - no error, no warning, the tags simply do not exist. So the file was deliberately rebuilt with the 1.21 folder name and run again: **39 of the 50 assertions failed**, which is every single one that asserts something is present. The suite can tell the difference between a working payload and a dead one.

**Can't be fixed with tags, on this version in particular:**
- Pam's Food Extended lists items from Crops and Trees as required entries in its own tags. With those two mods unable to load on 1.20.1, 16 of Food Extended's tags fail to load - including its berry and citrus families. That happens with or without Pantrywork installed, nothing here references those 16 tags, and only Pam's can fix it.
- Cultural Delights 0.16.7 deletes a few vanilla recipes by shipping empty files, which 1.20.1 cannot read. Harmless, logged on every boot, upstream's to fix.
- As on every version: a recipe that names an exact item id instead of a tag cannot be widened by any datapack, and several of these mods do exactly that.
